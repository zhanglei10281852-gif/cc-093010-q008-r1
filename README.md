# 全球健康创新试点运营服务

这是一个面向健康科技展会、临床合作机构、康复机构和产业伙伴的 Python 后端。服务使用 FastAPI 与 SQLite 管理健康创新产品、试点场地、证据材料、公众体验反馈、参数化体验方案、排队场次、站点租约、失败恢复、观察记录版本和人工干预。所有运行状态保存在单个本地数据库文件中，不需要另行部署数据库、缓存、消息队列或浏览器界面。

## 已有能力

- 产品目录：登记来源国家、所属机构、产品类别、用途、适用人群、风险级别与当前合规状态。
- 场地目录：维护展会体验点、医院、康复机构、研究机构和产业伙伴的能力、服务人群、伦理准备、可承接风险级别、开放时间与并发上限。
- 证据材料：按产品保存临床、性能、安全、合规和体验材料，使用内容摘要实现重复提交幂等，并支持接受或驳回。
- 体验反馈：按场地、场次引用和受众类型保存评分、标签、意见以及后续联系授权，重复反馈不会创建第二条记录。
- 体验方案：使用参数规则描述外骨骼、辅助诊断、数字疗法、慢病管理和数字中医等设备或服务的运行边界。
- 场次调度：提交方按项目和幂等键创建场次，执行站点按能力领取并获得有期限的租约。
- 执行回执：站点可以续租、提交观察记录或报告失败；可重试失败按照确定的退避时间重新排队。
- 失败恢复：租约到期后由恢复入口重新排队，达到最大尝试次数的场次转为失败。
- 人工干预：取消、人工重试、优先级调整和批量操作均保留操作者、原因、前后状态与批次标识。
- 名额协调：按产品类别、风险级别、适用人群、地区、场地能力、伦理准备和开放时间给出带理由的候选顺序；运营发起限时预留，医院接受、拒绝或附加条件，企业确认后容量才正式占用。
- 容量一致性：预留与确认全程使用即时事务和条件更新串行化，任何一方并发确认都只能产生一个成功名额；预留到期由受控时间规则释放。
- 目录联动：产品暂停或场地能力、容量、开放状态变化时，只撤销尚未生效的匹配并通知医院、企业和运营，已确认名额不受影响。
- 时间线与值班视图：记录容量从推荐、预留、答复、确认到释放或生效的每一步变化，值班人员重启服务后仍可查看等待答复、即将到期和已自动释放的记录。
- 身份审计：保留用户、角色、团队、会话、权限、审计事件和后台维护能力，敏感凭据只保存摘要。

## 运行环境

- Python 3.11
- SQLite 3，由 Python 标准库提供
- Linux、macOS 或 Windows

## 安装

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
```

默认数据库位于 `./data/health-innovation.db`。可复制 `.env.example`，并通过 `HEALTH_INNOVATION_DATABASE_PATH` 指定其他本地文件。

## 数据库初始化与检查

```bash
python -m app.cli init-db
python -m app.cli check-db
python tools/verify_sqlite.py
```

## 启动 API

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8432
```

健康检查：

```bash
curl -sS http://127.0.0.1:8432/api/system/health
```

产品、场地、证据和体验反馈接口使用 `/api/catalog` 前缀，体验方案、场次、领取、回执与恢复接口使用 `/api/pilots` 前缀，候选推荐、限时预留、双方确认、到期释放与容量时间线使用 `/api/matchings` 前缀。

## 试点名额协调流程

1. 生态合作负责人调用 `POST /api/matchings/recommend`，服务结合产品类别、风险级别、适用人群、地区、场地能力、伦理准备情况和开放时间，返回带评分维度与文字理由的候选顺序；不满足硬性条件的组合标记为不可选并给出阻断原因（例如高风险产品推荐给不具备对应能力或伦理准备的科室）。
2. 运营员对选定组合调用 `POST /api/matchings/reservations?actor=...` 发起限时预留，需提供受控的 `ttl_seconds`（15 分钟到 14 天）和幂等键。预留立即占用场地容量口径中的名额。
3. 医院调用 `POST /api/matchings/reservations/{code}/hospital-response`，选择接受、拒绝或附加条件。
4. 企业调用 `POST /api/matchings/reservations/{code}/enterprise-response` 确认或放弃；只有医院接受（或附加条件被接受）后企业确认，名额才转为 `confirmed` 正式占用容量。
5. 医院拒绝、企业放弃、运营撤销或预留到期都会释放容量并通知相关方；到期由 `POST /api/matchings/expire-due` 的受控时间规则处理，答复迟到时该名额也会在同一事务内先释放再拒绝答复。
6. 产品被暂停或场地能力、容量、开放状态变化时，只自动撤销尚未生效的匹配，已确认名额不动，撤销原因写入事件并发送给医院和企业。
7. 值班视图 `GET /api/matchings/inbox` 在打开时先应用一次时间规则，再汇总等待医院、等待企业和 24 小时内到期的名额；`GET /api/matchings/timeline` 按时间窗核对每一步容量变化（hold 占位、commit 生效、release 释放）。

名额状态：`reserved → hospital_accepted / hospital_conditional / hospital_rejected → confirmed / enterprise_declined / expired / revoked`。

```bash
python -m app.cli smoke
python -m app.cli pilot-demo
python -m app.cli matching-demo
```

`smoke` 在进程内检查根路径和健康接口。`pilot-demo` 会登记一个康复设备和体验场地，创建外骨骼步态体验方案，提交并领取场次，用于快速确认目录与试点运营链路。`matching-demo` 演示高风险数字疗法的候选推荐（能力不足的场地被排除）、限时预留、医院附加条件和企业确认。

```text
  api/              用户、角色、团队、认证、审计和系统接口

  repositories/     身份、审计和团队数据访问
  services/         身份、后台任务、维护和通用服务

  database.py       SQLite 连接、事务、表结构与基础权限

tools/               数据库完整性检查
```

## 数据一致性

SQLite 连接启用外键、WAL、busy timeout 和同步写入策略。产品目录、证据审阅、反馈提交、场次领取、执行回执、人工干预与名额预留确认使用即时事务；场次领取和名额状态流转通过条件更新避免重复分配或并发产生第二个成功名额，场地容量按未决预留与已确认名额统一计数。服务保存 UTC 时间字符串，测试可注入固定时钟验证退避、租约到期、预留到期和跨日配额。预留到期由可注入时钟的受控时间规则释放，值班视图打开时自动应用；审计记录会清理密码、令牌等敏感字段，体验反馈仅保存联系人摘要和是否允许后续联系。
